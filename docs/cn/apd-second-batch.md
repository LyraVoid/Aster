# APD 第二批：授权同步稳定性

参考 FolkPatch main `29851e4875fa3b3834e58cfb027ed51720182ce8` 的增量撤销策略，继续使用原始 APatch 的 supercall 接口。

## 行为变化

- 原来同步先撤销普通 UID 的所有 Root 授权，再重新加载配置。现在保留仍明确授权的 UID，只撤销配置中不再授权的 UID。UID 0 和 2000 延续原有保护。
- 仍通过原有 grant 接口加载配置中的目标 UID 和 SELinux 上下文，不引入默认授权、新应用自动授权、管理器专用白名单或定制 KernelPatch 指令。
- 内核授权列表为空时正常加载配置；列表缩小时只处理实际返回的 UID，不处理缓冲区补零。
- UID 监听器注册成功后立即同步一次，然后继续原来的事件监听和防抖。

## 配置一致性

管理器和 APD 在整个“读取、修改、写入、应用授权”过程持有同一文件锁 `/data/adb/ap/package_config.lock`。Java FileChannel 与 Rust fcntl 使用相同的 POSIX 记录锁，锁文件不会随 CSV 替换。

管理器改用同目录临时文件、同步数据、原子替换；APD 写回也采用这一方式。空配置写成包含 CSV 表头的文件，零字节文件不作为清空授权的有效指令。

管理器保存排除配置时保留该记录，只有回到默认状态才删除记录，避免已有授权切换为排除后丢失持久配置。界面状态更新及原有内核调用在配置保存后、同一把锁内执行，保存失败时不会按成功更新界面。

APD 在下列情况跳过本次内核授权修改：

- 配置缺失、读取失败、表头错误、记录损坏、非法配置值或相互冲突的共享 UID 配置。
- 系统包列表为空、编码或 UID 不合法、重复包名、缺失 UID、文件未完整结束。
- 文件超过 16 MiB、读取期间快照变化，或必要的配置写回失败。

同一包不同用户保留用户编号，仅更新 appId；卸载的包删除配置，重装后沿用原来的按包名更新 UID 规则，不新增自动授权策略。共享 UID 的一致配置允许合并处理，有冲突则跳过整次同步。

## 验证和边界

- 229 项 JVM 测试通过，包括原子替换、旧读者快照、失败清理和文件锁释放。
- 20 项 Rust 测试在 Linux 和 Android 真机通过，包括损坏快照不应用、有效空列表、共享 UID、多用户、重装映射、写回失败和跨进程锁互斥。
- Debug APK 构建成功。没有用这些测试调用真实内核授权接口或更改手机的授权配置，也没有自动安装、升级 APD 或重启。

管理器与 APD 需同时更新，才能完整使用共享锁。旧版本及外部工具不会参与新锁；APD 的重复快照检查只能降低此类并发风险，不能提供跨旧版本的事务保证。原始 KernelPatch 不提供整批授权事务，内核调用失败仍按原逻辑记录结果，不能将本次测试视为所有设备实际授权行为的保证。

本批不包含日志轮换、挂载逻辑或 KernelPatch 修改。
