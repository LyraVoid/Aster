# Magic mount 移植记录

来源：FolkPatch `main`，提交 `29851e4875fa3b3834e58cfb027ed51720182ce8`（已核对远端 main）。

`apd/src/magic_mount.rs` 的生产代码与该提交逐字节一致，文件末尾仅增加测试注册。目录树合并、tmpfs / bind mount、whiteout、opaque 目录、符号链接、SELinux 标签和独立分区处理均沿用上游实现。

## 接入方式

- 设置入口：设置 → 内核 → **Magic mount**。
- 标记文件：`/data/adb/.magic_mount_enable`；不存在时默认关闭。
- 开启时跳过元模块的 `metamount.sh`，在 `post-mount` 阶段脚本完成后执行内置挂载；关闭时继续使用元模块的挂载脚本。与上游一样，不改变其他元模块阶段脚本的执行。
- 工作目录、挂载源与上游一致：`get_tmp_path()/workdir/`、`APatch`。保留现有安全模式和 Magisk 检测前置退出逻辑。
- 设置写入成功后才更新开关和模块页横幅；更改挂载方式需要重启。

## 安装布局兼容

同步上游安装器的独立分区布局：真实内容保留在 `system/vendor`、`system/system_ext`、`system/product`，模块顶层提供指向这些目录的链接。

Aster 旧安装器生成的布局方向相反。开启 Magic mount 后，在进入上游挂载算法前，只转换确认为旧安装器形态的相对链接与真实目录。移动保留内容与文件属性；遇到错误回滚当前分区并终止本次内置挂载。模块自行定义的其他链接保持原状，禁用及 `skip_mount` 模块不参与转换。

## 模块提示

模块页仅在启用的模块需要挂载、Magic mount 关闭、且元模块不可用时显示横幅；文案提供两种挂载方式。模块安装完成后的元模块提醒弹窗及其探测、翻译资源已移除，安装日志和重启按钮保留。

## 验证

- Android 应用编译、打包及 224 项 JVM 测试通过。
- Android ARM64 守护进程编译通过；9 项 Rust 测试在连接手机的临时目录通过，涵盖文件合并、链接、tmpfs 判断、旧布局转换和重复执行。
- 测试未执行真实系统挂载，也未修改手机上现有模块或重启手机。实际开机挂载仍需在更新 AndroidPatch、开启开关并重启后验证。
