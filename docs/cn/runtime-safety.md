# 受保护的运行时操作

参考 FolkPatch main `29851e4875fa3b3834e58cfb027ed51720182ce8` 的 `fpd -hide` / `fpd -umount` 用途，重新实现安全流程。使用原始 APatch 安全模式接口及标准 Linux 挂载接口，不修改 KernelPatch。

## 使用方式

更新配套管理器与 AndroidPatch 后，进入 **设置 → 内核 → 受保护的运行时操作**。

1. 选择状态隐藏或输入模块资源路径后预检。预览显示实际属性变化或源文件与目标文件。
2. 点击“开始 60 秒试运行”。应用失败、试运行到期或检测到安全模式时自动尝试恢复。
3. 检查效果后选择“本次开机保留”，或者“恢复并关闭”。同时只允许一个会话。
4. 查看操作日志。恢复失败会明确显示错误并保留恢复记录，不会报告已经恢复成功。

两项默认关闭，不自动开机应用。保留只对当前 boot ID 有效，重启后保持关闭；旧启动的原值不会写入新启动的系统。退出安全模式也不会重新启用。

## 状态隐藏

仅处理已存在且确实需要变化的四项属性：

- `ro.boot.vbmeta.device_state` → `locked`
- `ro.boot.verifiedbootstate` → `green`
- `ro.boot.flash.locked` → `1`
- `ro.boot.veritymode` → `enforcing`

不会实际重新锁定 Bootloader，不修改 ADB、调试、日志、启动模式或 `persist.*` 配置，不承诺绕过硬件认证或应用检测。

执行前备份原值，每次写入后回读验证。单个 resetprop 子进程超时为 3 秒，失败后逆序恢复已经尝试的项目。恢复时若值被第三方改成原值和目标值之外的内容，不覆盖第三方修改，而是报告恢复未完成。

## 模块资源卸载

这是严格受限的卸载入口，不支持任意卸载列表。输入格式如 `mymodule/system/media/bootanimation.zip`，目标由分区路径确定。

目前只支持以下目录下的非空普通文件：`/system/media/`、`/product/media/`、`/vendor/media/`、`/system_ext/media/`、`/odm/media/`、`/system/fonts/`、`/product/fonts/`。

必须同时满足：

- 模块源文件和当前目标的设备号、inode、大小相同；源和目标均无符号链接。
- 目标是单层、只读、私有挂载，父挂载也为私有；目录、关键路径、共享/从属传播及未知挂载标志全部拒绝。
- 在独立挂载命名空间中预先卸载后，露出不同的有效底层文件，没有另一层同路径挂载；执行前再次核验完整 mountinfo 和文件身份。
- 能在恢复目录为模块源文件建立硬链接，要求同一文件系统；建立恢复绑定副本并保留原挂载标志。硬链接防止源文件删除后失去可恢复的目录项。
- 内核支持 `open_tree` / `move_mount` 文件描述符挂载接口，预检中会在独立命名空间实际演练卸载和恢复。

只使用普通卸载，不使用 `MNT_DETACH`，忙挂载直接拒绝。恢复时使用保留的挂载副本，核验目标及底层文件身份；第三方新挂载或改变底层文件时拒绝覆盖并保留备份。

现有 Magic mount 不保证每个绑定都是只读，也可能创建目录覆盖；这些挂载不会自动符合本功能条件。不会为通过检查而修改现有挂载权限。跨文件系统、模块镜像等无法建立硬链接的情况会被拒绝。

## 安全模式、恢复与日志

- 使用 Android 安全模式属性及原始 APatch `sc_su_get_safemode`。查询失败按不可启用处理，并对已有会话尝试恢复。
- 每个项目修改前先原子保存恢复意图并同步磁盘，失败时不会继续应用。
- 独立监督进程每秒检查安全状态、试运行期限；确认后仍保留监督。
- 现有 UID 监听器每 5 秒提供独立恢复检查，发现监督进程死亡后由恢复记录重试。PID 配合进程启动时间校验，避免 PID 复用误判。
- 启动阶段异步检查旧记录，不阻塞启动且绝不自动应用功能。
- 状态文件损坏时停止新操作；日志读取不依赖状态文件解析成功。
- 恢复失败保留记录和副本，阻止开启新的会话，允许查看日志和手动重试。

文件位于 `/data/adb/ap/runtime-safety/`，目录权限 0700，状态和日志文件为 0600。`state.json` 是原子替换的恢复记录；`audit.log` 和 `audit.previous.log` 各最多约 256 KiB，记录时间、预检/执行、项目内容、确认和恢复结果。日志写入失败时停止新的修改，但仍尽力恢复。

## 恢复边界

自动恢复不能等同于任意故障下保证恢复。内核不可中断挂起、磁盘损坏、系统杀死监督进程和 UID 监听器、以及有 Root 权限的第三方同时修改资源，可能延迟或阻止恢复。不会为了清除错误而强制卸载未知挂载或覆盖第三方状态；此时保留证据并显示失败。Linux 系统调用本身不能保证有限时间完成，启动检查因此采用异步方式。

更新 APD 后需重启或正常重启对应监听器，独立恢复监控才会进入新版本；不要只替换管理器就认为后台保障已经升级。
